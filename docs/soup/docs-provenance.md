# Soup documentation provenance

The local documentation is a complete snapshot of the 131 article URLs in the official [Soup documentation sitemap](https://trysoup.dev/sitemap.xml), retrieved on 2026-10-30 UTC (2026-10-31 in the workspace's Asia/Qyzylorda timezone). Navigation follows the 11 groups and 131 links in the official [Getting Started](https://trysoup.dev/docs/getting-started) sidebar.

Article bodies are preserved from each source page's server-rendered `<article>` element. The snapshot contains 1,516 headings including page titles and 667 code blocks. Getting Started contains all 16 headings and 14 code blocks, including the v0.76 and v0.75 upgrade sections, requirements, Docker, every optional extra, shell quoting notes, quick start, health check and demo.

The source describes Soup as Apache-2.0 licensed. The [upstream repository](https://github.com/MakazhanAlpamys/Soup) LICENSE and NOTICE were fetched at main commit `d0803fe8dcb3492d49e053234beeaaa4e401d078`; complete copies are retained in `src/soup/docs/LICENSE.upstream` and `src/soup/docs/NOTICE.upstream`. Upstream notice:

> Soup  
> Copyright 2026 Makazhan Alpamys and the Soup contributors

The local modifications replace the original presentation with the site's monospace, square-border theme, localized controls, responsive documentation navigation, a searchable index and copyable code. The article prose remains the original English, explicitly marked with `lang="en"`, `dir="ltr"` and a visible English-language notice. There is no claim that the source article bodies have been translated.

The importer removes the original styling, React hydration payloads, HTML comments, script elements and unapproved attributes. A reviewed element and attribute allowlist is applied. Code strings are decoded from their original HTML entities and otherwise unchanged. Known documentation links become locale-aware local routes; other project and external links retain their real absolute destinations. Repeated source IDs are assigned unique numeric suffixes, preserving the first occurrence and reserving all original IDs so existing inbound anchors retain their destination. This corrects two repeated headings on `adapter-check`: the audit section uses `exit-codes-2` and `json-2`; the check section retains `exit-codes` and `json`. Source attribution links point to each original article.

`scripts/import-soup-docs.mjs` refreshes the snapshot using the official sitemap, with six simultaneous fetches, retries and a temporary source cache. Run `node scripts/import-soup-docs.mjs --refresh` to fetch a fresh snapshot. `src/soup/docs/manifest.json` records source URLs, retrieval date, per-page SHA-256 hashes of the original complete HTML response, metadata and source section/code counts. Article JSON files live under `src/soup/docs/pages/` and load individually rather than bundling the whole corpus into every browser view. A compact inverted search index, generated from all prose and commands, loads only when a sidebar or index-page search is entered; both interfaces share the same search hook and cached index. Search normalizes punctuation and accents, accepts word prefixes and requires every query word to match. It is keyword search, not an AI or embedding-based search service.

Verification compared each of the 131 imported article text bodies to its cached original after removing the replaced code-language/copy UI: all 131 matched exactly. All 667 original code strings matched their local counterparts exactly. The importer also verifies 1,957 local documentation links, including all 517 fragment links, against the actual imported routes and element IDs; all resolve. No route aliases were needed. The all-article uniqueness regression test first reproduced the two duplicate IDs and now passes; every TOC entry has its own existing target. No existing body links referenced the two repeated anchors, so no ambiguous body-link destination required retargeting. No inline script, event-handler or style attributes survived sanitation. Search checks confirm body-only terms such as `pipx`, punctuation-normalized `private addresses` and code flags such as `--dry-run` find their expected pages. The copy failure path focuses and selects the exact code, announces the localized fallback instruction and keeps that instruction visible. Repository TypeScript and focused ESLint validation passed after the documentation components were added.
